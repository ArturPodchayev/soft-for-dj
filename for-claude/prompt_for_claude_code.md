# Контекст и первая задача — проект soft-for-dj (рабочее название: DJ Party 2.0)

## Кто я и что уже существует

Я (Artur, GitHub: ArturPodchayev) ранее построил и живьём обкатал на мероприятии в
American University of Technology (Узбекистан) систему **aut-dj-party**
(репозиторий: github.com/ArturPodchayev/aut-dj-party, приватный).

Это работающий MVP: гости сканируют QR-код → отправляют заявку на песню через
форму `/submit-aut` → модератор одобряет/отклоняет в `/admin-aut` → одобренные
треки показываются очередью на проекторном экране `/qr-display`. Стек:
Next.js (App Router) + Supabase (Postgres) + Vercel, WebGL-визуал (виниловая
пластинка, эквалайзер, ambient-фон), поллинг 1.5–2 сек для синхронизации
экранов, атомарная Postgres RPC-транзакция для переключения трека (чтобы не
было пустого экрана между треками), анти-фейк валидация номера телефона.

**Сейчас я в новой, отдельной папке/репозитории `soft-for-dj` — это НЕ ветка
aut-dj-party, а новый самостоятельный продукт.** Часть архитектуры из
aut-dj-party переносится (копированием кода, не общей зависимостью), но с
существенными изменениями и двумя целиком новыми модулями.

## Что переносим из aut-dj-party (проверено вживую, работает)

- Модель данных заявки и статусы: pending → approved/rejected → playing → played.
- Атомарная транзакция переключения текущего/следующего трека (одна RPC на оба
  поля разом — критично, чтобы клиенты никогда не видели промежуточное
  состояние с пустой очередью).
- Единый helper упорядочивания очереди — одна и та же логика сортировки должна
  использоваться и в UI модерации, и в логике переключения (в aut-dj-party была
  жёсткая ошибка именно из-за расхождения этой логики в двух местах — не
  повторять).
- Анти-фликер защита на клиенте (обработка гонки состояний при поллинге/пуше).
- Анти-фейк валидация телефона: список реальных префиксов операторов Узбекистана
  (90, 91, 93, 94, 95, 97, 98, 99, 33, 55, 77, 88) + эвристики на «дегенеративный»
  номер (палиндром, повтор цифр, последовательность, мало уникальных цифр).
- Каскад источников обложки/метаданных: iTunes → Genius → YouTube thumbnail.
- WebGL-компоненты проекторного экрана: виниловая пластинка, эквалайзер,
  ambient-фон, карточка в стиле liquid glass.

## Что меняем принципиально по сравнению с aut-dj-party

1. **Брендинг параметризуется с первого дня.** В aut-dj-party цвета/шрифты/тексты
   зашиты под один вуз (Tailwind-классы с хардкодом hex-цветов). Здесь с самого
   начала — конфиг на площадку/DJ (CSS-переменные или JSON-конфиг), потому что
   продукт задуман для нескольких диджеев по Ташкенту в будущем.
2. **Поллинг заменяется на Supabase Realtime (WebSocket push).** Вместо клиента,
   спрашивающего "что нового" каждые 1.5–2 сек, база сама пушит изменение
   подписчикам. Это устраняет саму идею задержки между действием модератора и
   обновлением экрана.
3. **Новый модуль: автопоиск + автоскачивание трека.** Отсутствует в
   aut-dj-party полностью. Срабатывает в момент approve в админке:
   - Цепочка источников по приоритету: **Hitmo (eu.hitmoz.com/search)** →
     **Sefon** → **Zaycev.net** → **MP3Juice**. Если нигде не нашли — флаг
     модератору на ручное скачивание.
   - **Обязательная проверка подлинности** перед принятием файла: нечёткое
     сравнение (fuzzy-match) артиста+названия с данными заявки, сверка
     длительности (допуск ±10 сек), фильтр по словам remix/cover/live/instrumental
     в названии результата (отсекать, если явно не заказывали). Три исхода:
     подтверждено / не уверены (на проверку модератору) / не найдено.
   - После подтверждения — переименование в `Artist - Title.mp3` и загрузка в
     Google Drive (через Google Drive API) в специальную папку.
   - Статус скачивания (`download_status`: pending/downloading/ready/failed)
     пишется обратно в БД и видно в админке.
4. **Новый модуль: интеграция с Serato + DJ-вью.** Тоже отсутствует в
   aut-dj-party.
   - Google Drive синхронизируется десктопным клиентом **на том же компьютере**,
     где стоит Serato (важно: НЕ отдельное устройство — уточнено с диджеем,
     у него один ноутбук на пати).
   - Serato использует нативную функцию **Watch Folder** — сама подхватывает
     новые файлы в библиотеку (crate) без участия диджея.
   - **Важное ограничение, не пытаться обойти:** у Serato нет официального API
     для удалённого управления воспроизведением. Кнопка play физически остаётся
     действием диджея на контроллере (Pioneer DDJ-SR2). Автоматизация закрывает
     только «найти и подготовить», не «включить».
   - **DJ-вью** (`/dj-view` или подобный роут) — обычная адаптивная
     (responsive) веб-страница с текущим+следующим треком и статусом готовности
     файла в реальном времени (Realtime-подписка). НЕ нужен отдельный экран
     выбора устройства — просто нормальный CSS, который сам подстраивается под
     ширину окна: полный экран, половина окна рядом с Serato, узкий экран
     телефона.

## Юридический момент (держать в уме, не решать сейчас)

Hitmo/Sefon/Zaycev.net/MP3Juice — сайты в серой юридической зоне (нет
официального API, скрейпинг HTML). Приемлемо для прототипа/личного DJ-использования.
При реальном масштабировании на других диджеев — надо будет отдельно
рассмотреть легальные источники. Не блокирует разработку сейчас, но не
предлагай выдавать это за «полностью легально».

Также: шрифт MADE Mirage в aut-dj-party куплен под тот проект — в новом
продукте использовать другой шрифт или отдельно проверить лицензию, не
копировать шрифтовые файлы автоматически.
